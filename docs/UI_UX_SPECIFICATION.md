# UI/UX-спецификация (ТЗ для Claude Design)

Документ передаётся в Claude Design как самостоятельное техническое задание. Реализация: Next.js (App Router), TypeScript, Tailwind CSS, shadcn/ui (Radix), MapLibre GL JS, Recharts, иконки Lucide. Контракты данных описаны в [API_SPECIFICATION.md](API_SPECIFICATION.md).

## 0. Главное правило для макетов

Продукт показывает **только реальные спутниковые данные**. В макетах допустимы нейтральные плейсхолдеры (`—`, серые скелетоны, подпись «пример разметки»). Нельзя рисовать правдоподобные «фейковые» пожары, числа и графики, которые могут попасть в код. Каждый экран проектируется в состояниях:

1. загрузка;
2. данные;
3. пусто (источник работает, обнаружений нет);
4. ошибка источника или API;
5. данные устарели (> 3 ч с последнего обновления);
6. сервер просыпается (холодный старт API до ~60 с).

## 1. Позиционирование и стиль

**Образ:** профессиональная консоль спутникового мониторинга, нечто среднее между операционным центром и научным инструментом. Не учебный CRUD и не маркетинговый лендинг.

- **Тема:** тёмная по умолчанию (карта и данные читаются лучше). Есть полноценная светлая тема и переключатель.
- **Характер:** спокойный, точный, плотный по информации. Акцент на карте и цифрах, минимум декора, без стоковых иллюстраций.
- **Типографика:**
  - интерфейс: Inter (или IBM Plex Sans) с кириллицей;
  - числа, координаты, время: моноширинный шрифт с табличными цифрами (JetBrains Mono или IBM Plex Mono), `font-variant-numeric: tabular-nums`;
  - шкала: 12 / 13 / 14 / 16 / 20 / 24 / 32 px; KPI 32–40 px.
- **Цвет:**
  - нейтральная база: холодный графит (тёмная тема: фон около `#0B0F14`, поверхности на 1–2 ступени светлее, тонкие полупрозрачные границы);
  - один холодный акцентный цвет (циан или бирюза) для интерактива и выделения;
  - **шкала риска** (огненная, упорядоченная по светлоте, различимая при дальтонизме): `low` (приглушённый жёлтый), `moderate` (янтарный), `high` (оранжево-красный), `very_high` (насыщенный малиново-красный). `unscored` / «без ML» показывается нейтральным серо-голубым. **Цвет никогда не является единственным носителем смысла**: дублируется размером или формой маркера и текстовой меткой;
  - статусы источников: ok, degraded, down, disabled, каждый с цветом и иконкой.
  - Все токены задаются через CSS-переменные для обеих тем. Контраст текста не ниже WCAG AA.
- **Анимации:** 150–250 мс, `ease-out`. Плавное появление маркеров, «пульс» только у обнаружений моложе 3 часов, анимированные переходы чисел в KPI. Всё отключается при `prefers-reduced-motion`.
- **Сетка:** 8 px, радиусы 6–10 px. Глубина в тёмной теме передаётся светлотой поверхностей, а не тенями.

## 2. Информационная архитектура и навигация

```
/                      Дашборд (Обзор)
/map                   Карта обнаружений
/detections/[id]       Детальная страница обнаружения
/clusters/[id]         Потенциальный очаг (группа обнаружений)
/analytics             Аналитика
/sources               Источники данных
/model                 ML-модель
/about                 Методология и термины
```

- **Desktop (≥ 1024 px):** левый сайдбар-навигация (иконка и подпись, сворачивается до иконок) и верхняя панель (название системы, выбор территории и периода, индикатор свежести данных, переключатели темы и языка).
- **Mobile (< 768 px):** нижняя tab-навигация: Обзор, Карта, Аналитика, Источники, Ещё (Модель, О системе).
- **Глобальные фильтры** (период, территория) хранятся в URL query (`?from=&to=&region=`), так что ссылкой можно поделиться и вернуться назад.
- Сценарии переходов:
  - дашборд → «Открыть на карте» (с текущими фильтрами);
  - карта → маркер → popup → «Подробнее» → `/detections/[id]` → «Показать очаг» → `/clusters/[id]`;
  - имя источника в любой карточке → `/sources#code`;
  - ML-оценка в любой карточке → `/model`.

## 4. Экраны

### 4.1. Дашборд `/`
**Цель:** за 5 секунд понять обстановку за последние 24 часа и за выбранный период.

Раскладка desktop (12 колонок):
1. **Ряд KPI** (4 карточки): «Обнаружений за 24 ч», «Обнаружений за период», «Активных потенциальных очагов», «Суммарная FRP за период». У каждой есть подпись источника и сравнение с предыдущим равным периодом (стрелка и %). Сравнение не показывается, если за прошлый период данных нет.
2. **Мини-карта** (8 колонок): сетка или heatmap за 24 часа, кнопка «Открыть карту».
3. **Свежесть источников** (4 колонки): статус, время последнего обновления и записи за 24 часа по каждому источнику.
4. **Динамика** (8 колонок): столбцы по дням за период, стек по спутникам. Интервалы-пробелы (`gap`) штрихуются с подписью «нет данных от источника».
5. **По регионам** (4 колонки): горизонтальный bar, топ-10.
6. **По спутникам** (6 колонок): bar.
7. **По уровням ML-оценки** (6 колонок): только при активной модели. Иначе карточка «ML-модель не активна» со ссылкой на `/model`.

Данные: `/stats/summary`, `/stats/timeseries`, `/stats/by-region`, `/detections/grid`, `/sources`.

### 4.2. Карта `/map` (центральный экран)
Карта занимает весь экран, поверх неё:
- **слева** сворачиваемая панель фильтров со счётчиком «Показано N из N» или предупреждением «Показаны агрегаты: слишком много точек»;
- **справа** выдвижная панель деталей выбранного обнаружения (на mobile это bottom sheet);
- **снизу** таймлайн-слайдер периода с гистограммой обнаружений по часам и возможностью «проиграть» период;
- **сверху справа** управление: zoom, переключатель подложки (тёмная и светлая векторные; спутниковая подложка ⚠ только если найдётся бесплатный источник с подходящей лицензией), слои (обнаружения, потенциальные очаги, границы регионов, heatmap), легенда, кнопка «Список» (табличная альтернатива карте).

Визуализация:
- **Маркер:** круг. Цвет задаёт уровень риска (или confidence без ML), радиус масштабируется по FRP (лог-шкала, 4–14 px). Ночные обнаружения обозначаются иконкой в popup. Свежие (< 3 ч) обнаружения пульсируют.
- **Кластер:** круг с числом. Цвет определяется максимальным риском внутри, размер зависит от количества. По клику карта приближается.
- **Мелкий масштаб** (zoom < 6 или ответ `truncated`): сетка или heatmap из `/detections/grid`.
- **Потенциальный очаг:** полупрозрачная оболочка.

**Popup маркера:** риск-бейдж, «Спутниковое обнаружение · VIIRS · NOAA-21», время UTC и местное, относительное время, координаты, FRP (МВт), confidence (как в источнике), ML-оценка (% и версия модели) или «без ML», «Получено системой: …», ссылки «Подробнее» и «Первоисточник (NASA FIRMS)».

Данные: `/detections`, `/detections/grid`, `/regions?geometry=true`, `/clusters`.

### 4.3. Детальная страница обнаружения `/detections/[id]`
Две колонки (на mobile одна).
- **Шапка:** «Спутниковое обнаружение #id», RiskBadge, явная надпись: «Термическая аномалия, обнаруженная спутником. Не является подтверждённым пожаром».
- **Левая колонка:**
  - мини-карта: точка, контур пикселя (scan × track), соседи за ±48 часов;
  - «Наблюдение»: время, спутник и инструмент, день/ночь, координаты, размер пикселя;
  - «Измерения»: FRP, яркостные температуры (с подписями каналов), confidence (исходное и нормализованное значение);
  - «Погода в момент наблюдения»: температура, влажность, ветер (стрелка), VPD, осадки за 7 дней. Подписи «ячейка 0,25°, модель, источник Open-Meteo» и «погода является фактором опасности, а не признаком пожара».
- **Правая колонка:**
  - «ML-оценка»: вероятность (крупно, со шкалой и порогами уровней), версия модели, вклад признаков (бары «повышает» и «понижает»), ссылка «Как работает модель». Без модели: «ML-оценка недоступна: модель не активна»;
  - «Потенциальный очаг»: число обнаружений, первое и последнее, суммарная FRP, ссылка на кластер;
  - «Происхождение данных»: источник и ссылка, продукт и версия (NRT/RT/URT), получено впервые и обновлено, ID запуска загрузки, SHA-256 ответа (сокращённо), ссылка на документацию продукта;
  - «История записи»: таймлайн изменений.

### 4.4. Потенциальный очаг `/clusters/[id]`
Карта с оболочкой и точками, таймлайн обнаружений, график FRP по времени, сортируемая таблица обнаружений, опционально блок «Оценка гари Sentinel-2 (dNBR)» с датами снимков, облачностью и дисклеймером.

### 4.5. Аналитика `/analytics`
Секции (вкладки или якоря):
1. **Динамика:** временной ряд, переключатели интервала (час, день, неделя, месяц), метрики (count, sum FRP, median FRP) и группировки (источник, спутник, регион, риск).
2. **Регионы:** хороплет и таблица (регион, count, доля, sum FRP).
3. **Спутники:** количество, медиана FRP, доля ночных обнаружений.
4. **FRP:** гистограмма (лог-шкала), ряд медианы и суммы.
5. **Сравнение периодов:** выбор A и B, наложенные ряды, карточки разницы.
6. **Сезонность:** heatmap «год × месяц».
7. **Погодные факторы:** распределения T, RH, ветра и VPD в точках обнаружений, при активной модели с разбивкой по риску. Дисклеймер.

У каждого графика есть: заголовок, подзаголовок с активными фильтрами и источником, tooltip с точными значениями, «Скачать CSV», «Показать таблицей», состояния пусто и ошибка. **Пробелы в данных визуально отличаются от нулей.**

### 4.6. Источники данных `/sources`
Карточка на каждый источник: название, провайдер, тип данных, описание (что даёт, частота, задержка, разрешение), **статус-бейдж**, «Последнее успешное обновление», «Записей за 24 ч / всего», «Последняя ошибка» (время и текст, раскрывается), ссылки «Официальный сайт», «Документация», «Лицензия». Таблица последних запусков (время, HTTP, получено, вставлено, обновлено, отклонено, статус).
Информационный блок: «Suomi NPP VIIRS прекратил выдачу новых данных 02.11.2026. Используются NOAA-20 и NOAA-21» и «MODIS (Terra, Aqua) завершает работу в 2027 г.».

### 4.7. ML-модель `/model`
- **Шапка:** название, версия, статус (`active` / `rejected` / «модель не обучена»), дата обучения.
- **«Что оценивает модель»:** простым языком: постановка, смысл метки, что модель **не** делает.
- **Признаки:** таблица (группа, признак, описание, источник).
- **Данные обучения:** источники, период, территория, число примеров, баланс классов.
- **Схема валидации:** диаграмма временного разбиения train / validation / test и пространственных блоков.
- **Метрики:** модель против baseline (PR-AUC, ROC-AUC, Precision, Recall, F1, Brier) с ДИ, PR-кривая, кривая калибровки, срезы. **Без оценённой модели блок пуст с объяснением, цифры не рисуются.**
- **Ограничения**, **дрейф** (гистограмма вероятностей за 7 и 30 дней), **история версий** (включая отклонённые), ссылки на артефакт и отчёт.

### 4.8. О системе `/about`
Методология, глоссарий (обнаружение, потенциальный очаг, ML-оценка, подтверждённый пожар, FRP, confidence, NRT), ограничения данных (центр пикселя, ложные срабатывания, облачность), цитирование источников.

## 5. Микротекст (обязательные формулировки)

| Вместо | Использовать |
|---|---|
| «Пожар» (для точки) | «Спутниковое обнаружение» / «Термическая аномалия» |
| «Очаг пожара» (для кластера) | «Потенциальный очаг» |
| «Вероятность пожара 87 %» | «ML-оценка: 87 % (модель v1.0.0)» |
| «Опасность: высокая» без модели | «Уровень по данным FIRMS: high confidence (без ML)» |

## 6. Адаптивность

| Ширина | Поведение |
|---|---|
| ≥ 1440 | Дашборд в 12 колонок, на карте открыты обе панели |
| 1024–1439 | Сайдбар свёрнут до иконок, панель деталей карты накладывается поверх |
| 768–1023 | Дашборд в 2 колонки, фильтры карты в выдвижной панели |
| < 768 | Одна колонка, нижняя навигация, полноэкранная карта, фильтры и детали в bottom sheet (peek, половина, полный экран). Широкие графики скроллятся внутри своей карточки, у страницы нет горизонтального скролла |

Минимальная ширина 360 px. Touch-цели не меньше 44 px.

## 7. Доступность

- Контраст WCAG AA, видимые фокус-кольца, полный доступ с клавиатуры (табличный режим «Список» на `/map` как альтернатива карте).
- `aria-live` для обновлений счётчиков и баннеров.
- У графиков есть текстовая альтернатива (таблица).
- `prefers-reduced-motion` отключает пульсацию и анимацию чисел.

## 8. Производительность (требования к дизайну)

- Скелетоны вместо полноэкранных спиннеров.
- Смена фильтра обновляет источник данных карты без пересоздания карты.
- Мини-карта на дашборде загружается лениво, чтобы первый экран не ждал библиотеку карты.

## 9. Что нужно получить от Claude Design

1. Дизайн-токены (цвета обеих тем, шкала риска, типографика, отступы, радиусы) в виде CSS-переменных и конфигурации Tailwind.
2. Макеты экранов §4 в desktop- и mobile-версии, каждый в состояниях §0.
3. Спецификацию компонентов §3 (варианты, размеры, состояния).
4. Стиль карты: маркеры, кластеры, сетка или heatmap, оболочки, легенда, popup и стиль подложки (JSON-стиль MapLibre или параметры для выбранного бесплатного источника тайлов).
5. Стиль графиков: палитра серий, оси, сетка, tooltip, обозначение пробелов в данных.
