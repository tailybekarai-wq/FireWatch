## 2. NASA FIRMS: подробно

### 2.1. Доступ
- Ключ MAP_KEY выдаётся бесплатно по e-mail на странице `https://firms.modaps.eosdis.nasa.gov/api/map_key/`.
- Проверка остатка транзакций: инструмент «Check status» на той же странице.
- Лимит: **5 000 транзакций за 10 минут**. Увеличение возможно по запросу.

### 2.2. Area API
```
GET https://firms.modaps.eosdis.nasa.gov/api/area/csv/{MAP_KEY}/{SOURCE}/{W,S,E,N}/{DAY_RANGE}
GET https://firms.modaps.eosdis.nasa.gov/api/area/csv/{MAP_KEY}/{SOURCE}/{W,S,E,N}/{DAY_RANGE}/{YYYY-MM-DD}
```
- `bbox` задаётся в порядке `west,south,east,north`, допускается `world`.
- `DAY_RANGE` от 1 до 5.
- Доступность дат проверяется через `/api/data_availability/`.

### 2.3. Продукты (SOURCE)
| SOURCE | Статус для проекта |
|---|---|
| `VIIRS_NOAA20_NRT` | **Используется** (оперативно) |
| `VIIRS_NOAA21_NRT` | **Используется** (оперативно) |
| `MODIS_NRT` | Используется до окончания миссий (дополнительно) |
| `VIIRS_NOAA20_SP`, `VIIRS_NOAA21_SP`, `VIIRS_SNPP_SP`, `MODIS_SP` | Архив и обучение |
| `VIIRS_SNPP_NRT` | **Не используется**: производство прекращено 2026-11-02 13:00 UTC |
| `LANDSAT_NRT` | Только США и Канада, не используется |

### 2.4. Задержка и версии
- NRT публикуется **в течение 3 часов** после пролёта (best effort).
- RT (≤ 30 мин) и URT (единицы минут) доступны только для США, юга Канады и севера Мексики. Они удаляются после прихода соответствующих NRT-записей или через 6 часов.
- Поле `version` оканчивается на `NRT`, `RT` или `URT`.
- SP (научное качество) выходит с лагом **2–3 месяца**.

### 2.5. Атрибуты (используемые)
VIIRS: `latitude, longitude, bright_ti4, scan, track, acq_date, acq_time, satellite, instrument, confidence (l/n/h), version, bright_ti5, frp, daynight`.
MODIS: `latitude, longitude, brightness, scan, track, acq_date, acq_time, satellite, instrument, confidence (0–100), version, bright_t31, frp, daynight`.
⚠ Точные имена колонок сверить на странице «Active Fire Data Attributes for MODIS and VIIRS» и по первой реальной выгрузке. Парсер должен падать с явной ошибкой при изменении схемы.
⚠ Поле `type` (0: растительный пожар, 1: вулкан, 2: иной статичный источник, 3: в море) по документации FIRMS **есть только в SP/архивных продуктах, не в NRT**. Проверить по архивной выгрузке.

### 2.6. Ограничения интерпретации (из документации FIRMS)
- Координаты — это **центр пикселя**. Сам пожар обычно меньше пикселя (375 м для VIIRS и около 1 км для MODIS в надире, к краям полосы обзора пиксель больше).
- Возможны ложные срабатывания: газовые факелы, вулканы, промышленность, перегретые дымовые шлейфы ночью, артефакты над Южно-Атлантической аномалией.
- FIRMS предупреждает, что использовать confidence следует с осторожностью, а порог подбирается эмпирически.

### 2.7. Условия использования
NASA придерживается политики полного и открытого обмена данными. Требуется указание «NASA FIRMS» и ссылка, а также ознакомление с LANCE Disclaimer. Цитирование выводится на страницах UI и в README.

## 3. Copernicus и Sentinel-2

- **Роль:** не источник обнаружений. Пролёт над точкой раз в 2–5 дней (по двум или трём спутникам), снимки могут быть закрыты облаками и дымом. Используется для оценки площади гари после события.
- **Каналы для индексов:** B8 (NIR, 10 м), B12 (SWIR2, 20 м), B4 (Red, 10 м), SCL (маска облаков).
  - NDVI = (B8 − B4) / (B8 + B4)
  - NBR = (B8 − B12) / (B8 + B12)
  - dNBR = NBR_до − NBR_после
- **Реализация (опционально, этап 8+):** Sentinel Hub Statistical API считает средний dNBR в буфере вокруг очага без скачивания снимков. Это экономит квоту: один запрос на очаг, порядок PU уточнить расчётом.
- **Квоты:** 10 000 PU в месяц, что достаточно для десятков и сотен запросов в месяц. Результаты кэшируются в БД.

## 4. Open-Meteo

- Переменные: `temperature_2m, relative_humidity_2m, wind_speed_10m, wind_direction_10m, precipitation, vapour_pressure_deficit, soil_moisture_0_to_7cm, et0_fao_evapotranspiration`.
- **Экономия квоты:** погода запрашивается не по каждому обнаружению, а по ячейке сетки 0,25° (разрешение ERA5) за сутки. Несколько обнаружений в одной ячейке используют один ответ.
- **Лицензия:** использование некоммерческое (дипломный проект подходит), атрибуция CC BY 4.0 в футере UI.

## 5. Административные границы

Нужна открытая лицензия, совместимая с публикацией, и **актуальное деление Казахстана** (17 областей и 3 города республиканского значения, после создания Абайской, Жетысуской и Улытауской областей в 2022 году).

Проверено 2026-11-02:
- **geoBoundaries KAZ ADM1** (`gbOpen`): лицензия ODbL 1.0, но `boundaryYearRepresented = 2017` и всего 16 единиц. **Устарел: в нём нет областей 2022 года.** Не используется.
- **OpenStreetMap:** ODbL, деление поддерживается в актуальном виде. **Выбран.** Загружается командой `python -m firewatch_pipeline.regions`:
  - основной путь: Overpass API (`admin_level=4`, `ISO3166-2=KZ-*`);
  - резервный путь, если публичные Overpass перегружены: OSM API 0.6. Подрегионы берутся из членов `subarea` отношения Казахстана `r214665` (их 20), геометрия — из `/relation/{id}/full.json`, граница страны — объединение областей;
  - ответ кэшируется в `data/raw/` (не коммитится), в БД геометрия упрощается до ~50 м;
  - загрузчик ничего не пишет, если найдено не ровно 1 страна и 20 единиц первого уровня;
  - районы (`admin_level=6`) пока не загружаются.
- **GADM:** **только некоммерческое использование, запрет на перераспространение.** Не подходит для публичного репозитория.
- **Natural Earth:** public domain, грубая детализация, деление может быть устаревшим. Только запасной вариант для ADM0.

## 6. Что исследовано и отклонено

| Вариант | Причина отказа |
|---|---|
| VIIRS_SNPP_NRT | Прекращён 2026-11-02 |
| GOES / Himawari / Meteosat (геостационарные) | Высокая частота, но низкое разрешение (2 км и хуже). Покрытие зависит от территории. Отложено: можно подключить позже через FIRMS (там есть геостационарные слои) ⚠ |
